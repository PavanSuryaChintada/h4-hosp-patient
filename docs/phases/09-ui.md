# Phase 9 — UI on Real Data

**Time:** 4h. **Cuttable.** Do not start until Phases 1–8 are green.

---

## Scope

The Round 1 React app, repointed from hardcoded fixtures to the real pipeline output. `SHARED-DESIGN-SYSTEM.md` and `H4-DESIGN.md` from the Round 1 pack apply unchanged — same tokens, same zero-radius, same IBM Plex, same no-gradients rule.

---

## Requirements

**R1 — Read pipeline output, do not recompute.** `run.py` emits a UI-shaped JSON alongside the submission CSV. The app imports it. The UI must never contain detection logic — **a second implementation that drifts from the first is worse than no UI at all.**

**R2 — The collapse toggle survives.** `Collapsed (3)` vs `Every pair (11)` on real patients. It was the best moment in Round 1 and it is better with real data behind it.

**R3 — Raw → resolved stays visible.** Every medication shows the original string, the resolved generic, the confidence, and abstentions marked `verify manually`. It makes the hardest part of the problem legible.

**R4 — The evaluation screen shows the real numbers**, including the missed near-misses. Pull directly from `eval/reports/`, never retyped.

**R5 — Pick three demo patients and pin them:** the collapse hero, the no-issue-found patient, and one with an abstention. A `?demo=1` flag surfaces them at the top of the queue so the video never involves scrolling.

**R6 — Never on the scoring path.** The UI lives in `/ui`, is excluded from the submission zip unless asked for, and nothing in `/src` imports from it.

---

## Deliverables

- [ ] `run.py --ui-output ui/src/data/` writing the UI JSON
- [ ] Round 1 app repointed, all five screens working on real data
- [ ] The three pinned demo patients
- [ ] A screenshot set for the report

## Acceptance

- The app runs with the network off.
- Every number shown matches `eval/reports/` exactly — spot-check three.
- No detection logic anywhere under `/ui`.
