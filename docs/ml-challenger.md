## What these comparisons can and cannot say

Holdout is not a clean out-of-sample estimate for the rules. The condition vocabulary and stop markers were built by reading all training text, holdout included (docs/DECISIONS.md D-025), and the resolver's synonym list comes from dev failures plus general prescribing knowledge (D-014), which git cannot prove line by line. So the rules' perfect holdout rows are optimistic, and the hidden test set may score lower. Each comparison below is fair only as "how a learned model does on the same patients", not as rules against model generalisation. The models' own numbers are out of sample: none trained or tuned on holdout.

## Stage 1: reading drug names

A matcher trained on the labelled lines resolved **32 holdout lines confidently wrong** (the shipped resolver: 0), and abstained on 9. A confidently wrong name is the failure that hides a real interaction: the line is checked as the wrong drug, and nothing on screen says to verify it. An abstention is shown to a person as "verify manually" instead.

- **Model:** character 3- and 4-gram TF-IDF, nearest neighbour. Trained on the reference names and the 7131 labelled lines of the dev split.
- **Abstains** below similarity 0.3 or a margin under 0.0, chosen by 5-fold cross-validation inside dev (accuracy 0.9729 on 7131 lines).

## Stage 3: which alerts are worth a prescriber's time

The textbook version predicts adverse drug events or whether a prescriber acts on an alert. This dataset records neither, so that model cannot be trained honestly here. Instead, gradient-boosted trees learn which of a standard hospital check's alerts match a real issue that is not minor, and hold back the rest.
